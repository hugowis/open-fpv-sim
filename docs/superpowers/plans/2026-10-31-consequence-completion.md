## The tasks, and the order they should land

1. **#28 — rotated boxes in the world** (representation first, per the epic's own ordering). One rotation datum in the world data, consumed everywhere an object is used — collision, the radio and video raycasts (#168's blocking search), the Godot draw — or an explicit ruling naming which consumers rotate and why the rest do not. The wire carries objects, so a rotation field is likely a protocol bump (17) — ruled in the spec with the regeneration choreography. Worlds without rotation: byte-identical, no golden moves.
2. **#156 — collisions between objects** (#29, part 1 of 2). Quad-to-object contact exists since M3c; this is objects answering each other. #29's "props with each other" phrase has an open point the spec must rule (what collides with what, and at what cost per tick) — recorded as a ruling, flagged for the maintainer.
3. **#157 — crash damage: degrade and repair** (#29, part 2 of 2). Damage on the fault seams (`vehicle.rs`'s `Fault::PropDamage`/`MotorFailure`), a bent prop flying worse and shaking the gyro, constants as provenance-marked estimates, repair as the workbench action (#128's seam), `Load` as the reset; the audio thud (#158's one-thud-per-collision-kind) extended only if the spec rules it.
4. **The minors tail** — one B6-style batch plan: #164 (`battery_current_a` tops out at 4× the ESC limit — the clamp, not a draw), #165 (a measured magnetometer into Betaflight SITL: a reserved state-datagram block + `virtualMagSet`), #146 (the Windows `sitl_process` ready-line timeout flake — B6's "check the record after merge" verdict: no `sitl_process` timeout in the post-B6 main record, so it stays monitored, and this batch takes it only if a fresh strike lands; the failure that DID land post-#168 on main is a different flake — the hover-determinism divergence — tracked as its own issue, not #146's symptom).

The pairs are independent in design but share two surfaces that need coordination. **The wire:** all three spec+plan pairs assume the next protocol number (17) and two assume the same field — #28's `WorldObject.yaw_deg` and #156's `WorldObject.motion` both take field 9 — so the pairs land sequentially and each executor re-verifies `PROTOCOL_VERSION` and takes the next free number and field (#173's `[look]` section queues behind them all). **The goldens:** the epic rule is that non-opt-in worlds move nothing, and #164's ruling is the one sanctioned exception — the winding-current clamp rides every scripted flight, so its removal legitimately changes the radio-golden recordings on all four OS files (the minors plan schedules the regeneration with B6's choreography); any other golden diff is a bug.
