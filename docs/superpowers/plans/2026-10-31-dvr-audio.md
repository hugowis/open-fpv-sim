# Audio in the DVR Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The MP4 export of a DVR recording carries an AAC audio track synthesised from the recording with part 1's synthesis, deterministically.

**Architecture:** While a feed records, `ofs-client` appends the audio inputs (one record per accepted video frame, one per collision event) to a text sidecar `<name>.audio` beside the AVI. The MP4 export replays the sidecar through the unchanged `ofs_audio::Audio` facade into a temp raw-PCM file, and ffmpeg muxes it as a second input next to libx264. The image-sequence export and `ofs-audio` are untouched; no protocol change (stays 15).

**Tech Stack:** Rust (`ofs-client`, `ofs-godot`), GDScript tests (Godot 4.7.2), ffmpeg on `PATH` at export time.

**Spec:** `docs/superpowers/specs/2026-10-31-dvr-audio-design.md` (read it first; its Rulings are binding).

## Global Constraints

- `ofs-audio` is not modified. `ofs-sim` and its crates must not depend on `ofs-audio` (the guard test `crates/ofs-audio/tests/isolation.rs` stays green); `ofs-client` may.
- Protocol stays 15; do not touch `proto/`, `crates/ofs-proto`, the Python client, `crates/ofs-rf`, `crates/ofs-radio`, `crates/ofs-config/src/world.rs`, `godot/world/`, `worlds/` (other sessions work there).
- Live audio behaviour must not change: `OfsClient.audio_render` produces the same samples for the same telemetry before and after.
- One frame at 50 fps (`ofs_client::dvr::DVR_FPS`) is exactly `SAMPLE_RATE / DVR_FPS = 882` samples; assert the division is exact at compile time.
- PCM is signed 16-bit little-endian mono at 44100 Hz: `round(clamp(x, -1, 1) * 32767)` as `i16`.
- Sidecar: first line `ofs-dvr-audio 1`, then `C <event_time_s>` and `F <state_time_s> <collision_speed_mps> <airspeed_mps> <descent_mps> <n> <rpm_1..rpm_n> <cmd_1..cmd_n>` lines, LF, numbers via `f64` `Display` (exact round trip). `F` of a frame written before any telemetry: `F NaN 0 0 0 0`.
- ffmpeg audio arguments: second input `-f s16le -ar 44100 -ac 1 -i <pcm>`, `-c:a aac -b:a 128k`, `-shortest`. Existing video arguments are unchanged. The export never overwrites and leaves no temp file.
- Files stay LF: `tr -cd '\r' < file | wc -c` prints 0 for every file touched.
- Rust tests run in WSL (`docs/dev-setup.md`); Godot tests via `bash scripts/run-godot-tests.sh` with `OFS_GODOT_DL=/mnt/c/dev/open-fpv-sim/build/godot-dl` and `OFS_SIM_BIN` set to your debug build (the client prefers a stale `target/release/ofs-sim`); read the WHOLE Godot output (it prints `0 failed` even after a SCRIPT ERROR).
- Do not regress `_free_stem` / the `REC_<ts>` naming in `godot/ui/dvr.gd`.
- Commit locally after each task; never push, never open a PR. Commit messages end with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.
- `clippy -D warnings` clean for `ofs-client` and `ofs-godot`.

## Review Focus

- A sidecar with a truncated last line (crash), NaN/inf numbers, a mismatched `n`, an unknown header: tolerated tail, otherwise an error naming the line; never a panic or NaN samples. (Task 2)
- A frame the writer queue dropped must not get an audio record (audio length stays equal to video length). (Task 3)
- A refused start (AVI exists; sidecar not creatable) leaves neither file behind; a leftover `.audio` without its AVI does not block a start. (Task 3)
- A missing sidecar exports a silent MP4 as today; a bad sidecar fails before ffmpeg is spawned; no temp file survives any outcome. (Task 4)
- A collision event arriving before its state, and one after the last frame: same thud rules as live (`Audio::frame`). (Task 2)

### Task 2: the sidecar log and the PCM replay

**Files:**
- Create: `crates/ofs-client/src/dvr_audio.rs`; Modify: `crates/ofs-client/src/lib.rs` (`pub mod dvr_audio;`)
- Test: `crates/ofs-client/tests/dvr_audio.rs`

**Interfaces:**
- Consumes: `ofs_audio::{Audio, AudioInput, SAMPLE_RATE}`, `crate::dvr::DVR_FPS`.
- Produces (all in `ofs_client::dvr_audio`):
  - `pub const SAMPLES_PER_FRAME: usize = 882;` (compile-time-asserted equal to `SAMPLE_RATE / DVR_FPS`, exact).
  - `pub struct AudioLog` with `pub fn create(path: &Path) -> Result<AudioLog, String>` (creates/truncates the file, writes the header, `BufWriter`), `pub fn collision(&mut self, time_s: f64)`, `pub fn frame(&mut self, input: Option<(&AudioInput, f64 /*state_time_s*/, f64 /*collision_speed_mps*/)>)` (`None` writes the silent `F NaN 0 0 0 0` record), `pub fn finish(self) -> Result<(), String>` (flush). A write error is remembered and returned by `finish`, never a panic.
  - `pub fn write_pcm(sidecar: &Path, out: &mut dyn Write) -> Result<u64, String>`: replays the log (`Audio::new()`; `C` -> `collision_event`; `F` -> `frame(&input, time, speed, SAMPLES_PER_FRAME)`), writes each chunk as s16le to `out`, returns the number of `F` records. A truncated last line (no trailing LF and unparsable) is ignored; any other bad line, a wrong header, or an `n` that does not match the number of numbers is `Err("<file>: line N: ...")`. `descent`/`airspeed` etc. come back exactly (f64 parse of `Display`).
