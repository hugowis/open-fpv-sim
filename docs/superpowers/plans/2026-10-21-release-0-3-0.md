**Goal:** Ship `open-fpv-sim` 0.3.0: six items, each planned, implemented, independently reviewed and tested before the
next one starts, then one release commit that bumps the version and changelog. The tag, the push of it and the PyPI

finding before the next item starts. The release phase re-runs everything, because six separate gates do not prove the
combination.

**Tech Stack:** Rust (workspace, MSRV 1.85), Python 3.10+, Godot 4.7.2, protobuf/proto3, MCAP and Foxglove.

## Design Calls

These are decisions made while planning, not open questions. The reviewer checks the implementation against them; the
user can still overrule any of them before implementation starts.

1. **This is 0.3.0, not 0.2.1.** The batch adds features and changes the gRPC protocol, so it is a minor bump at 0.x,
   exactly as 0.2.0 was over 0.1.1.
2. **#23 is a new `DownlinkLoss` fault, not a direction on `RadioLoss`.** `RadioLoss` keeps its uplink meaning and its
   Python API. The new fault takes `fraction` in [0, 1] and affects only what the handset hears. Its randomness comes
   from a **second dedicated stream** (`elrs-faults-downlink`, `fixed-faults-downlink`), so the existing uplink fault
   draws and every fault-inactive golden stay identical.
3. **#22 is `radio.telemetry_slot_divisor`**, not a new `[radio.elrs]` table. The allowed values are `1, 2, 4, 8, 16,
   32, 64, 128`, default `4`; `0`/off is out of scope. The `fixed` link uses the same field, because it has the same
   slot model and a second config knob would be a lie.
4. **#44 uses the host path separator** (`;` on Windows, `:` elsewhere), like `std::env::split_paths`, but empty
   entries are dropped. A single path behaves exactly as today. The first root that has a given kind/id wins; roots
   layer per part, not wholesale. The repro bundle merges its roots into its own `library/` with first-match-wins, so a
   replayer's `OFS_LIBRARY` still never reaches it.
5. **#56 records `tx` and `link_loss`, not only a transmitter column.** The K key calls `client.set_radio_loss`, a
   fault; a `transmitter`-only column would not replay K (checked in `godot/scripts/app.gd`, `set_radio_cut`). The
   column is named `link_loss` (1 = the K cut is active), not `radio_loss`, because `RadioLoss` is a different,
   fractional fault. Both columns are optional in the CSV, so every existing file plays exactly as before.
6. **#38 makes the F2 toggle the one start/stop path.** D and the resize auto-stop call the same setter; the checkbox
   is synced from `dvr.recording`, never the other way round. The HUD gets a `REC` indicator because there is none.
7. **#48 is investigation and documentation only.** If it finds that a code fix is needed (for example periodic chunk
   flushing), file a follow-up issue with the evidence and do not expand 0.3.0. The deliverable is an honest page a
   user can act on, with the Foxglove version and the exact error.
8. **The release notes lead with the protocol bump and the two additive CSV columns.** An old Python client cannot talk
   to a 0.3.0 server; an old CSV plays unchanged; a new CSV does not replay on 0.2.0, because that parser rejects
   unknown columns. Say both plainly.

## Review Gates

After each item, a **fresh reviewer** (not the implementer) gets: the issue body, the item's commits, the plan section
and the commands the implementer ran. The reviewer reads the code around the diff, not only the diff, and answers:

- Does the change do what the issue's "Done when" asks, and nothing more?
- Is the failure path right (invalid input, missing file, second root, fault off, no DVR, a writer that fails)?
- Are the tests meaningful: would they fail without the change? Is the determinism/default claim proven?
- Is anything now stale (README, roadmap, docs table, protocol line, changelog)?

The reviewer writes findings as `blocking` / `should fix` / `nit`. Blocking and should-fix findings are fixed and the
item's suite is rerun before the next item starts. The verdict (reviewer, commit range, result) goes in the release PR
body. A review that finds nothing still records the checks it ran.

The same gate applies to the release commit, with one addition: a second reviewer checks the changelog and the upgrade
notes against the merged behaviour, because that is the page users read first.

## Item 3 — #23: downlink loss

**Why third:** it is the only protocol change, and it rebases on the settled `LinkParams` from item 2.

**Acceptance:** a new `DownlinkLoss { fraction }` fault drops downlink packets (telemetry slots and downlink LQ) without
touching uplink control; `fraction = 0` is a no-op; the fault is in the proto, the Python API, the journal, the active
fault list and the CLI/README catalog; the protocol is 13; a run with no downlink fault is byte-identical to 0.2.0.

### Task 3.1 — The radio model: a signal and a dedicated downlink draw

**Files:** `crates/ofs-core/src/names.rs`, `crates/ofs-radio/src/parts.rs`, `crates/ofs-radio/src/elrs.rs`,
`crates/ofs-radio/src/fixed.rs`, `crates/ofs-radio/tests/elrs.rs`, `crates/ofs-radio/tests/fixed.rs`.

**Interface:** add `pub const FAULT_RADIO_DOWNLINK_LOSS_FRACTION: &str =
"fault.radio.downlink_loss_fraction";` to `names`. `FaultSignals` gains the signal and
`pub fn downlink_survives(&self, bus: &Bus, fault_draw: f64) -> bool` (the same shape as `survives`, reading only the

`model_rng(seed, "elrs-faults-downlink")`; on `FixedLink`, the same with `"fixed-faults-downlink"`. Draw **one** number
per packet from that stream and apply the heard-downlink decision:
`downlink_received &&= self.faults.downlink_survives(bus, draw)`. Keep the model's own `downlink_draw` and the uplink
fault stream untouched.

## Item 4 — #56: the inputs recording replays the link state

**Why fourth:** it needs the `RadioLinkLoss` fault plumbing that item 3 has just made consistent, and it changes the
CSV parser/recorder, which no later item touches.

**Acceptance:** a recording captures `tx` and `link_loss` alongside the sticks, writes a row whenever either changes
(not only when a stick moves), and `play_inputs` applies both. A 0.2.0 CSV with only stick columns parses and plays
exactly as before; a new recording of a K cut replays the cut.

### Task 4.1 — The CSV model gains two optional columns

**Files:** `crates/ofs-sim/src/inputs.rs`, `crates/ofs-sim/src/inputs_recorder.rs`,
`crates/ofs-sim/tests/inputs_recording.rs`.

**Interface:** replace the column vector's `Stick` with
```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum Column {
    Stick(Stick),
    Transmitter,
    LinkLoss,
}
```
`COLUMNS` becomes the 11 names (`t_s`, the eight sticks, `tx`, `link_loss`). `Inputs.columns: Vec<Column>`. `parse`

## Risks and Their Early Signals

- **#56's borrow restructure** in `apply_due` can silently change the journal order. Early signal: the existing
  journal/replay tests fail. Fix by collecting due rows first, then applying; never hold `self.playback` across a
  `self.set_transmitter`/`self.apply_fault`.
- **#23's protocol bump** can leave a stale Python stub or constant. Early signal: the proto guard test or the Python
  handshake test fails. Both files are in Task 3.3 for that reason.
- **#22's default** can drift a golden. Early signal: `radio_golden` fails without a change to the default. Do not
  re-record; find the field that leaked into the default path.
- **#44's bundle merge** can hide a part that only exists in the second root, or let the replayer's environment in.
  Early signal: the repro test with a hostile `OFS_LIBRARY` fails. The bundle must own its merged library.
- **#38's checkbox** can loop (set_dvr emits, then the handler starts a second recording). Early signal: the Godot
  test asserts one start per press; `set_dvr` has no `emit`.
- **#48** can turn into a code project. The gate is a document; a code fix is a follow-up issue, not a scope increase.
