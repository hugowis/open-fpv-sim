# macOS test fidelity Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stop the macOS tests that "pass" without comparing anything: record per-architecture radio goldens for macOS (both the radio's own and the vehicle's recorded flight), and replace the held-serial-port early return with a real macOS behaviour test plus a portable error-path test.

**Architecture:** Both golden file names become `<name>.<os>.digests` for Windows/Linux (unchanged) and `<name>.macos-<arch>.digests` for macOS: `elrs.*` in `ofs-radio` and `radio-flight.*` in `ofs-sim`. The files are generated by the manual macOS survey workflow (which has both an Apple silicon and an Intel runner), downloaded, and committed. The live held-port test is not compiled on macOS; a macOS-only live test pins the observed BSD `SO_REUSEADDR` behaviour, while a fake-SITL test covers the simulator's retry/error mapping on every OS. `docs/research/macos.md` records both changes.

**Tech Stack:** Rust 1.85 (workspace MSRV), Cargo, GitHub Actions (`macos-latest`, `macos-15-intel`), Godot-free.

**Spec:** PR #101's "Not done / deferred minors" (`docs/research/macos.md`, sections "macOS differences in the tests, fixed" and "Not done, and why"), issue #68.

## Global Constraints

- Windows and Linux golden files must not change. The Windows/Linux names and bytes are part of the compatibility contract; only the macOS path is added.
- MSRV is 1.85; no new crates.
- A test with no golden file for its OS/architecture must fail with an instruction, not print and return. An unsupported OS may still skip, but macOS is supported.
- The macOS live tests run with `--ignored`; do not use `#[ignore]` as a macOS-specific skip because `cargo test -- --ignored` runs ignored tests too. Use `#[cfg]` to compile the real test out on macOS.
- Run `cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets --locked -- -D warnings`, and `cargo test --workspace --locked` before the final commit.

## Review Focus

- **libm variation by architecture.** Apple silicon and Intel may produce different f64 bits; one macOS file for both would make one runner fail. The file name must include the architecture.
- **Golden drift.** `OFS_GOLDEN_WRITE=1` must only be run on purpose; a survey run that regenerates every time would hide a regression. Gate generation behind a manual boolean input.
- **The held-port test.** The BSD bind semantics are the subject of the test, not a bug to paper over. Pin the observed behaviour on macOS and test the error mapping independently with a fake SITL.
- **Live-test selection.** On macOS the new behaviour test must actually run under `--ignored`; the old test must not silently pass.
- **Documentation truth.** `docs/research/macos.md` must stop saying "two tests return early" once it is no longer true.

```rust
/// The golden file name for an OS/architecture pair, or None where none is recorded. macOS is split by
/// architecture because the two GitHub runners are separate libm builds.
fn golden_file_name(os: &str, arch: &str) -> Option<String> {
    match (os, arch) {
        ("windows", _) => Some("elrs.windows.digests".into()),
        ("linux", _) => Some("elrs.linux.digests".into()),
        ("macos", "aarch64") => Some("elrs.macos-aarch64.digests".into()),
```

Add this test beside `a_bind_that_succeeds_after_retries_starts_the_session` in `crates/ofs-fc/tests/sitl_errors.rs`:

```rust
/// A permanent bind failure (the 20 retries are spent) must fail the start and keep the errno on the record.
/// This is the parser/error-mapping half of the live test, so it runs on macOS where SITL's own BSD bind
/// check cannot refuse a held port.
#[test]
fn a_sitl_that_reports_a_spent_bind_fails_with_the_errno() {
    use ofs_fc::sitl::process::SitlProcess;
    let _guard = PORTS.lock().unwrap_or_else(|e| e.into_inner());
    let dir = tempfile::tempdir().unwrap();
    let script = "i=1; while [ $i -le 20 ]; do \
                  echo \"bind port 5761 for UART1 retry $i/20 (errno 48)\" >&2; \
                  i=$((i+1)); done; \
                  echo 'bind port 5761 for UART1 failed!! after 20 attempts (errno 48)' >&2; \
                  sleep 5";
    let cfg = config(dir.path(), &["sh", "-c", script]);
    std::fs::create_dir_all(&cfg.launch.workdir).unwrap();
    std::fs::write(cfg.launch.workdir.join("eeprom.bin"), [0u8; 16]).unwrap();
    std::fs::copy(&cfg.launch.diff_file, cfg.launch.workdir.join("betaflight.diff")).unwrap();
    let err = SitlProcess::start(&cfg).err().expect("a spent bind fails the start");
    let text = err.to_string();
    assert!(text.contains("bind port 5761 for UART1 failed!! after 20 attempts"), "the spent retries are on the record: {text}");
    assert!(text.contains("errno 48"), "the failure names the errno: {text}");
}
```

```rust
/// macOS's BSD `SO_REUSEADDR` lets SITL's wildcard bind coexist with a listener on 127.0.0.1:5761; the
/// documented behaviour is that the real SITL still starts. Pinning that here makes the platform difference
/// visible instead of returning early and showing a pass. The simulator's own UDP 9003 probe, and the fake
/// SITL error test, cover a genuinely stale process.
#[cfg(target_os = "macos")]
#[test]
#[ignore]
fn a_held_tcp_port_does_not_stop_sitl_on_macos() {
    let launch = argv("OFS_SITL_LAUNCH");
    assert!(!launch.is_empty(), "set OFS_SITL_LAUNCH");
    let dir = tempfile::tempdir().unwrap();
    let cfg = LaunchConfig {
        launch,
        cleanup: vec![],
        workdir: dir.path().join("fc"),
        diff_file: OSD_DIFF.into(),
        startup_timeout: Duration::from_secs(15),
    };
    std::fs::create_dir_all(&cfg.workdir).unwrap();
    std::fs::copy(OSD_DIFF, cfg.workdir.join("betaflight.diff")).unwrap();
    let _holder = std::net::TcpListener::bind("127.0.0.1:5761").unwrap();
    let started = ofs_fc::sitl::process::SitlProcess::start(&cfg);
    assert!(
        started.is_ok(),
        "macOS lets SITL bind alongside the holder: {:?}",
        started.err().map(|e| e.to_string())
    );
}
```
