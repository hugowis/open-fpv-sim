# Release 0.2.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prepare release 0.2.0 of `open-fpv-sim` (phases 2 and 3: M5 to M8c) so that tagging `v0.2.0` publishes it to PyPI: one version everywhere, a changelog that tells a user what changed and how to upgrade, and a verified package.

**Architecture:** A version bump in the two places that carry it (`Cargo.toml`'s `[workspace.package]` and `python/pyproject.toml`, plus `Cargo.lock`), a test that keeps them and the changelog in step, the changelog's unreleased milestone sections folded under a dated 0.2.0 heading with a capability summary and upgrade notes, and a clean-venv check of the built wheel and sdist. The tag, the push of it and the PyPI approval are **not** part of this plan's PR: they publish to the world and wait for the maintainer's explicit go-ahead.

**Tech Stack:** Cargo, Python packaging (`build`, `twine`), Keep a Changelog.

**Spec:** none; the 0.1.0 release (`CHANGELOG.md`, `CONTRIBUTING.md` "Releasing") is the precedent.

## Global Constraints

- No functional change: the diff is versions, changelog, docs and one guard test. `cargo test --workspace --locked`, clippy and the Python suite stay green.
- **Line endings:** never rewrite a file through Python text mode on Windows (CRLF); use Edit/Write or `sed -i` on LF files. Check new files with `git ls-files --eol`.
- Worktree-isolated sessions refuse heredocs and compound git commands: use Edit/Write; split commands.
- Commit trailers: a blank line, then `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>` on its own line.
- **Nothing is tagged, pushed as a tag, published or released in this plan.**

## Design calls (decided here; the executor ledgers any change)

1. **Version 0.2.0**, not 0.1.1: it adds features and breaks the gRPC protocol (10 to 12), the Rust API (`Vehicle::set_sticks` returns a `Result`) and recordings' channel set, which is a minor bump at 0.x.
2. **One version everywhere.** `[workspace.package] version` (so `ofs-sim --version` and the handshake's `server_version` say 0.2.0), `python/pyproject.toml`, and the workspace crates' entries in `Cargo.lock` (updated by cargo, committed; CI builds `--locked`). A guard test (`python/tests/test_release.py`) fails when the two sources disagree, when `Cargo.lock` lags, or when `CHANGELOG.md` has no `## <version> — ` heading for the current version.
3. **The changelog.** The ten "Unreleased" milestone sections (M5 to M8c and the v1 close-out) move under one heading `## 0.2.0 — 2026-10-17 (phases 2 and 3)`, demoted one level (each `## Unreleased — X` becomes `### X`, its `### Added/Changed/Fixed` become `####`), under a short capability summary in the style of the 0.1.0 entry and an "Upgrading from 0.1.0" list; a fresh empty `## Unreleased` stays on top. The summary and the upgrade list are written from the sections below them, not from memory.
4. **Upgrade notes must cover:** protocol 12 (a 0.1.0 client or server is refused at the handshake, so the Python package and `ofs-sim` must be the same release); rebuild Betaflight SITL with `scripts/build-sitl.sh` (the patch changed: reboot reply drop, M7a); the Rust API break; recordings gain channels (inflow, per-cell battery, temperatures) and change a few (`battery.*` now matches 16 signals; temperatures at 100 Hz), so scripts that count or select by pattern need a look; golden digests; stricter config validation (`windmill_j0`, resistance growth); repro bundles and `stabilize`; the Godot game gained the lap line and gates.
5. **Verification before the tag, in the PR:** build the wheel and sdist, `twine check`, install the wheel in a clean venv and run the import, version and a Load against a built `ofs-sim` (as CI's wheel step does), and confirm PyPI has only 0.1.0 (`pip index versions open-fpv-sim`).

## Review Focus

- The guard test fails when only one of the two versions is bumped (task 1).
- The changelog keeps every line of every milestone section, only re-headed (task 2).
- Nothing in the diff changes behaviour; the handshake still works between the Python package and `ofs-sim` of the same version (task 1, 3).
