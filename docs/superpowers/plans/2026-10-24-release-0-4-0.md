# Release 0.4.0 Plan

**Goal:** Ship `open-fpv-sim` 0.4.0 from the open issues: the race course gets finished (gate size and tilt, lap limit,
reset, next-gate highlight), a failed Betaflight session's repro bundle carries the settings it failed with, part
provenance is readable over the API, and the macOS job becomes trustworthy enough to gate on. One release branch cut
from `origin/main` at `230333d` (0.3.0), one commit per logical change, an independent review gate after each item,
then one release commit (version, changelog, `test_release.py` guard). The tag, its push and the PyPI approval wait for
the maintainer's go-ahead, exactly as in `2026-10-21-release-0-3-0.md`.

**Why this set.** 0.3.0 closed the radio axis. What the issues leave, grouped:

## Global Constraints

Same as 0.3.0: `cargo fmt --all -- --check` is **not** a gate (repo not rustfmt-clean; do not run it over existing
files); clippy `-D warnings` and `cargo test --workspace --locked` clean after every task; `python -m pytest python/tests`
green; Godot `scripts/run-godot-tests.sh unit` after Godot items and `all` before the release; live SITL files one at a
time with `OFS_SITL_LAUNCH` set; goldens stay byte-identical unless a task says it re-records them (and says why).

- **Protocol 13 -> 14, once.** #103, #104 and #43 all change messages. They share the single bump to 14 (made by the
  first of them to land; the others extend it). Update `crates/ofs-proto/src/lib.rs`, `python/ofs/client.py` and the
  guard in `crates/ofs-proto/tests/messages.rs`. A protocol-13 client or server is refused at the handshake; the
  changelog "Upgrade" line says so.
- **Worlds without the new fields behave exactly as today.** Every new `[[gates]]` / race field has a default that
  reproduces 0.3.0, and `worlds/circuit.toml` still laps in `test_circuit.py` and the live Betaflight circuit test.
- One `Closes #n` per line in each PR/commit body (GitHub closes only the first issue otherwise).

## Order

Chosen so shared files change once: tiny first, then the protocol work, then CI, then the release.

### 1. #117 reader error names a still-running recording (S)
- `python/ofs/reader.py`: add the third cause and the workaround (`sim.recording.stop()`, or `sim.log`, which stops
  and returns it) to the "unfinished recording" message. Keep it a `ValueError`.
- Test: the existing unfinished-file test asserts the new wording. Docs: one line in `docs/research/mcap-determinism.md`
  ("Reading a recording while it is being written") if it quotes the message.

### 2. #43 part provenance over the API (S-M, protocol 14)
- `proto/ofs/v1/sim.proto` (vehicle description gains per-part provenance: source plus the value's kind
  `datasheet|measured|estimated`), `crates/ofs-sim/src/server.rs`, `crates/ofs-config` (`Provenance` already exists),
  `python/ofs/client.py` (a `provenance` property on the loaded-vehicle description).
- Design call: expose the **part-level** provenance the loader already validates, not a per-field breakdown; per-field
  is a later extension (new proto field). Tests: Rust round trip on a library quad; Python test reads it for the
  shipped quad and finds no part without one.

### 3. #103 gate opening and tilt (M-L, protocol 14)
- `crates/ofs-config/src/world.rs` (`GateSection`: optional `tilt_deg` / roll+pitch, quad half-extent source),
  `crates/ofs-sim/src/race.rs` (crossing against the tilted plane; clearance test against the opening), proto
  `Gate`, `crates/ofs-godot/src/lib.rs` + `godot/world/` (frame drawn tilted), `docs/race-timing.md`.
- **Open ruling (needs the maintainer, see below):** a quad that clips a post/bar is "no pass" or a separate
  `gate_hit` event. Recommendation: **`gate_hit` event, no lap credit**, so a script can tell "missed" from "clipped".
- Quad size: use the hull's bounding sphere from the loaded config (no new quad field); an explicit gate-level
  `margin_m` override defaults to 0 only if the hull cannot be derived.
- Tests: analytic table (centre, edge, corner, backwards, tilted, clipped) plus the circuit still lapping.

### 4. #104 lap limit, reset, next-gate highlight (M-L, protocol 14)
- World field for the cap (`laps = N`, absent = unlimited), a `finished` flag in `State.race`, a reset request
  (`ResetRace`) that zeroes clock, splits and laps and emits an event, `race.*` signals show it.
- Rust/Python clients, Godot key (suggest **N**) and F2 entry, highlight driven by `race.next_gate` with start/finish
  drawn distinctly. Do it after #103 so the gate drawing changes once.
- Tests: limiter stops at N, reset zeroes everything, GDScript unit test for the highlight selection, Python
  `reset_race()` against `circuit.toml`. Docs: `docs/race-timing.md` ("Not included" shrinks), `docs/roadmap.md`.

### 5. #106 repro bundle captures the EEPROM at failure (M, risky)
- `crates/ofs-sim/src/repro.rs` (`FIRMWARE_STATE`, `BundleSource`, `snapshot_firmware`), `server.rs` (~298),
  `session.rs` (failure path), `docs/repro-bundle.md`.
- Design call: **snapshot on observed EEPROM save, keep the latest good copy, and at failure take whichever is newer
  after SITL exits (or a bounded wait for exit)**; a copy taken while SITL is alive may be torn, so write via
  temp-file + rename and fall back to the Load-time copy if the final copy fails a size/CRC sanity check. Decide
  between "wait for exit" and "on each save" in a short spike first; document the choice and the mid-write case.
- Test (the issue's): load, change a setting over the Configurator port, fail the session, replay the bundle, read
  the changed setting. Live (WSL) test; no-Configurator sessions bundle byte-identically to today.

### 6. #118 macOS Godot e2e flake (M, investigation)
- Evidence is CI-only (3 runs, three different failures). Do cheap and honest, in order: (a) make the `held_fields`
  and DVR-frame checks wait for the first rendered field before counting; (b) if the MoltenVK abort recurs, run the
  macOS Godot step with `--rendering-driver opengl3` or the software path; (c) only then a one-shot rerun that
  reports the attempt count.
- Done when: 10 consecutive `ci.yml` runs of the `macos` job are green on the branch/main, which is the record the
  roadmap asks for before promoting `macos` into `publish.needs`. **Promoting it is a separate, maintainer-approved
  change**, not part of this item.

### Stretch (only if 1-6 are done and green)
- **#107** CI job for the native Windows SITL (`msys2/setup-msys2`, non-blocking, artifact with the exe + two DLLs).
  Unknown runtime of the SITL build; budget a day and do not block the release on it.
- **#37** image-sequence export (optional, no new mandatory dependency; `ffmpeg` on `PATH` is opportunistic).

## Release phase
1. Re-run everything on the combined branch: Windows Rust + clippy, WSL Linux with live SITL
   (`sitl_live`, `vtx_live`), all Python (`test_sitl_*.py` one at a time), Godot `all`, benchmark gate.
2. Release commit: bump `Cargo.toml` / `pyproject.toml` / `Cargo.lock`, dated `0.4.0` CHANGELOG block with an
   "Upgrade" line (protocol 14; any repro bundle recorded by 0.3.0 still replays, a protocol-13 client does not
   connect), roadmap/known-limitations edits, `test_release.py` green.
3. PR, CI green on all jobs, then **stop**: tag `v0.4.0`, push the tag and approve the `pypi` environment only on the
   maintainer's explicit go-ahead. Optionally publish a GitHub Release page (not done for 0.2.0/0.3.0).

## Rulings needed before implementation
1. **Version:** 0.4.0 (new features + protocol change, minor at 0.x). Assumed.
2. **#103:** `gate_hit` event vs plain "no pass" for a clipped gate (recommended: `gate_hit`).
3. **#106:** wait-for-exit vs snapshot-on-save (recommended: spike, then snapshot-on-save with a final post-exit copy).
4. **Scope size:** six items as above, or add the stretch items (#107, #37) to the committed scope.
5. **#118:** acceptable to start with test-tolerance changes and escalate to the renderer switch only if it recurs?

## Risks
- #106 is the only item that can surprise: SITL's EEPROM write timing is upstream behaviour; the spike decides it.
- #103/#104 touch the gate golden-ish tests (circuit lap times may shift by a tick if the clearance test is stricter
  than the centre test); the plan treats a changed circuit time as a finding to explain, not a golden to regenerate.
- #118 cannot be reproduced locally; "fixed" means a clean CI record, not one green run.
- Phase-6 physics issues (#65, #28, #27) were deliberately left for a release that can afford a research page and
  golden churn each.
